# Entregáveis

## 1. Base React, navegação e regras de dados
- [x] Utilizar exclusivamente HTML5, CSS3, JavaScript e React. Não utilizar TypeScript, Tailwind CSS, Bootstrap, bibliotecas de componentes ou outras frameworks de frontend.
- [x] Desenvolver exclusivamente o frontend; não criar backend nem base de dados.
- [x] Implementar navegação funcional entre todas as páginas.
- [x] Utilizar React para os componentes e JavaScript para a lógica; utilizar HTML semântico e CSS puro para toda a estilização.
- [x] Organizar os ficheiros de forma simples, modular e reutilizável.
- [x] Preparar a estrutura para futura ligação ao backend do utilizador, sem inventar endpoints ou contratos de API.
- [x] Não inventar bolsas, mentores, preços, avaliações, estatísticas ou utilizadores; não utilizar dados fictícios para preencher as páginas.
- [x] Não simular pagamentos, autenticação ou gravações como se fossem reais.
- [x] Quando não existirem dados, apresentar listas vazias e mensagens neutras.

## 2. Apresentação, responsividade e estados
- [x] Criar uma interface minimalista, elegante e profissional, usando azul-escuro, azul principal, branco e cinza-claro.
- [x] Usar tipografia moderna e legível, navegação intuitiva, cartões simples e consistentes e formulários organizados.
- [x] Implementar menus adaptáveis a dispositivos móveis e layout responsivo para telemóveis, tablets e computadores.
- [x] Implementar estados visuais de carregamento, erro e ausência de dados.

## 3. Página inicial e bolsas
- [x] A página inicial apresenta a plataforma, navegação e pesquisa de bolsas.
- [x] A área de bolsas inclui listagem, pesquisa, filtros e detalhes das oportunidades.
- [x] Sem oportunidades reais, manter listas vazias e apresentar mensagens neutras; não inventar oportunidades nem dados.

## 4. Mentores e perfis
- [x] A área de mentores inclui listagem, perfis, especialidades, preços e disponibilidade.
- [x] Não inventar mentores, especialidades associadas a pessoas, preços, avaliações ou disponibilidades; na ausência de dados, mostrar estado vazio neutro.

## 5. Interfaces de autenticação
- [x] Disponibilizar interfaces distintas para registo, login e recuperação de palavra-passe.
- [x] Não simular autenticação nem apresentar uma sessão iniciada ou envio realizado; comunicar que estas ações aguardam integração.

## 6. Área do estudante
- [x] Disponibilizar a área do estudante com perfil, bolsas guardadas, acompanhamento de candidaturas, documentos e mentorias.
- [x] Sem dados reais, apresentar listas/áreas vazias e mensagens neutras; não aparentar guardar perfil, documentos ou candidaturas.

## 7. Área do mentor
- [x] Disponibilizar a área do mentor com perfil profissional, serviços, calendário, reservas e rendimentos.
- [x] Sem dados reais, apresentar áreas vazias e mensagens neutras; não inventar serviços, disponibilidade, reservas ou rendimentos.

## 8. Agendamento e checkout
- [x] Disponibilizar fluxo/interface de agendamento com seleção de serviços e horários, preparado para futura integração.
- [x] Disponibilizar interface de checkout preparada para integração futura, sem processar pagamentos.
- [x] Não simular uma reserva, pagamento ou gravação como real; não inventar serviços, horários ou preços.

## 9. Painel administrativo
- [x] Disponibilizar interfaces administrativas para gestão de bolsas, utilizadores, mentores e reservas.
- [x] Sem dados reais, apresentar tabelas/listas vazias e mensagens neutras; não inventar utilizadores ou registos.

## 10. Funcionamento sem backend e preparação de entrega
- [x] O projeto deve funcionar sem backend e estar preparado para receber dados reais quando a integração for realizada.
- [x] Implementar todas as páginas, componentes, formulários, menus e interações visuais solicitados.
- [x] Não desenvolver funcionalidades de servidor nem instalar tecnologias fora das quatro tecnologias especificadas.
- [x] Manter rotas e interfaces sem contratos de API inventados, e sem publicar a aplicação sem pedido explícito.
