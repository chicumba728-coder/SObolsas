## Design Specificity Verdict

**LLM assessment.** There is a real point of view here and it is worth keeping: an editorial-institutional minimalism built on a *route / next-step* motif — the ascending line in the brand mark, the numbered `01/02/03` path cards, the `path-tile` blocks. That motif is genuinely authored for a product about "finding the next step", and it survives in the one place generic templates never bother: the logo. So this is not a blank-slate rewrite; it is a refinement job.

But the rest of the surface still carries the generic-SaaS and AI-template signature in its bones. The homepage hero sits on a `linear-gradient(115deg, #fff, #f8faff)` with a radial-gradient `hero-visual__halo`, floating `box-shadow` cards and a dashed decorative line. The portal uses a full-width navy/blue "welcome banner" with an oversized rotated letter (`portal-welcome__symbol`) — the canonical automated-dashboard opener. Authentication pairs a rounded card with a dark `auth-aside` framed by decorative concentric circles. Section after section repeats the exact composition "eyebrow + headline + one line + right-aligned text link", and the homepage links the same two destinations (Bolsas, Mentores) five times before the fold is over.

Most telling: the product is *about clarity*, yet its default experience is a monotone wall of disclaimers. Nearly every route is `Notice + EmptyState + copy` all saying the same thing — "aguarda integração", "não inventámos dados". The honesty is admirable and non-negotiable, but it is over-communicated and, ironically, it is the least clear part of the app.

**Deterministic scan.** `impeccable detect --json src` returned `[]` (exit code 0) — clean. `index.html` and `public/` are likewise clean. The mechanical rules for decorative gradients, emoji-as-UI, placeholder text ("Lorem ipsum", "John Doe", "Coming soon"), conflicting competing-action buttons and the rest fired nothing. That is a genuine result, not a failure: the slop here is editorial and structural (slogans, redundant composition, dev artifacts, scaffolding references), which the token-level detector is not designed to catch. Assessment A carries this critique.

**Visual overlays.** Browser automation is not exposed in this session, so no live server was started and no in-page overlay was injected. Fallback signal: source review + a clean CLI scan. Any "here's the overlay in your browser" claim would be false; there is none.

## Overall Impression

The technical and accessibility foundations are better than the average hand-built React app: real design tokens, a skip link, `:focus-visible`, a global `prefers-reduced-motion` block, semantic `nav`/`main`, labelled fields, honest empty states. What holds it back is not bad code — it is (a) a residual AI/template footprint in decoration, copy and scaffolding, (b) a homepage that says the same thing five ways, and (c) a product that talks about itself ("preparada para integração") more than it helps the user do anything. The single biggest opportunity: convert the "everything is pending" chorus into one calm, quiet status treatment, and reinvest that freed attention into one strong, specific hero and a homepage that commits to a single path.

## What's Working

1. **The route/next-step motif.** The brand mark (open page + ascending path) and the numbered path cards give the product an identity that a competitor could not reuse unchanged. Protect it.
2. **Honest empty states with zero fabricated data.** `emptyData.js` is a real integration boundary, and no metric, testimonial, price, or fake user has crept in. This satisfies a core constraint and is rarer than it sounds.
3. **Accessibility plumbing.** Skip link, focus-visible outlines, reduced-motion block, semantic landmarks, `aria-current` on active nav, `role="status"`/`role="alert"` on states, and 44px+ targets. The bones are correct; only a few fixes are needed.

## Priority Issues

### [P1] Residual AI/scaffolding footprint in files and UI
- **What:** A Manus CDN logo URL lives in `app.config.ts`; `public/manus-routes.json` (and a `dist` copy) is referenced by `README.md`; and the admin area ships development artifacts as product UI — `StatePreview` ("Pré-visualização dos estados de interface") and `AdminEntryForm` ("Antrevisão da interface").
- **Why it matters:** These are brand-foreign references to code-generation/scaffolding tooling and internal previews. They break trust and read as an unfinished build, directly violating the "no scaffolding credits / no dev artifacts" requirement.
- **Fix:** Delete `app.config.ts` and the Manus route manifest (and its `dist` copy), drop the README reference, and remove/repurpose the state-preview and entry-preview panels so admin shows only real management affordances.
- **Suggested command:** `/impeccable distill`

### [P1] Every page repeats the same "integration pending" disclaimer
- **What:** `Notice` + `EmptyState` pairs appear on HomePage, ScholarshipsPage, MentorsPage, BookingPage, CheckoutPage, every StudentPage view, every MentorPage view and the whole Admin surface — all paraphrasing "aguarda integração / não inventámos dados".
- **Why it matters:** The repetition is the loudest signal in the app and makes a finished product look unfinished. Users stop reading it after the second screen, so the honesty stops working.
- **Fix:** Introduce a single, quiet, dismissible/Once-per-session system status treatment for the "no live data" condition, then let each empty state carry only *context-specific*, actionable copy. Reserve loud notices for genuinely exceptional states.
- **Suggested command:** `/impeccable distill`

### [P1] Homepage is redundant and slogan-driven
- **What:** Four sections stack the same "eyebrow + big line + text link" pattern; Bolsas and Mentores are linked five times (hero links, opportunities section link, three path tiles, mentor strip); the headings are generic slogans ("O próximo passo começa com informação clara.", "Uma plataforma, vários caminhos", "Encontre o apoio certo para cada etapa.", "Orientação sem atalhos.").
- **Why it matters:** The hierarchy flattens — every section competes equally — and slogan copy lowers the sense of authenticity without helping the visitor choose.
- **Fix:** Commit to one hero, collapse the middle into a single "how it works / what you can do" block, keep one clear primary action, and rewrite headings as concrete, product-truthful statements.
- **Suggested command:** `/impeccable distill` then `/impeccable clarify`

### [P2] Inconsistent primitives and invalid semantics
- **What:** Hand-rolled `.form-field` inputs (ScholarshipsPage, Booking, admin toolbar) duplicate the `Field` component; border radii are hard-coded at 6/7/8/9/10/11/12/13/14/22/30/999px; `Notice` uses the non-existent `role="note"`; `DataTable` renders a `thead` with no `tbody` and positions its empty state outside the table.
- **Why it matters:** Similar controls look and behave slightly differently, and the invalid role/table structure degrade the screen-reader experience Sam depends on.
- **Fix:** Route all fields through `Field`/`TextAreaField`/`SearchField`, consolidate radii into two or three tokens, replace `role="note"` with a valid pattern, and give `DataTable` a real `tbody` with a merged empty row.
- **Suggested command:** `/impeccable audit`

### [P2] Feedback and help gaps
- **What:** No loading/success feedback on any action; the scholarship filters and admin search change copy but filter nothing; Esc/outside-click never restore focus; there is no help surface; the footer "Contacto" is an empty `mailto:`.
- **Why it matters:** Users get no confirmation that anything happened, and the inert search/filters imply capability that isn't there (Riley will test exactly this).
- **Fix:** Make inert controls honestly inert (or clearly labelled as not yet active), add a lightweight help/contact path, add focus return to header menus, and standardise action feedback.
- **Suggested command:** `/impeccable harden`

### [P3] Decorative residue and polish
- **What:** Hero gradient and halo, the dashed `hero-visual__line`, oversized rotated monogram tiles, arrow glyphs (`↗ → ⌄ × +`) used as icons, and the dark `auth-aside` circles.
- **Why it matters:** Small, but they're the exact tells that make the surface look machine-assembled.
- **Fix:** Remove non-functional decoration, replace glyphs with restrained inline SVG or plain text, and tighten the motion budget.
- **Suggested command:** `/impeccable polish`

## Persona Red Flags

**Jordan (First-Timer)** — The "Áreas" trigger doesn't say which area is *yours* or what's behind it. "Agendamento" is a top-level destination that can't actually book anything, so the first click leads to a dead end. Every page then repeats "ligada à plataforma", a phrase Jordan has no definition for.

**Sam (Accessibility-Dependent)** — `Notice` emits `role="note"`, which is not a valid ARIA role, so announcements are unreliable. `DataTable` has no `tbody`, breaking table semantics. Closing the header dropdown or mobile menu with Esc leaves focus on `document.body`, forcing Sam to tab from the top of the page. `PortalLayout` calls `scrollIntoView({behavior:'smooth'})` and the router uses `behavior:'instant'` in JS, which the CSS reduced-motion rule does not govern.

**Riley (Stress Tester)** — Submitting the scholarship filters toggles the copy to "Resultados para os filtros aplicados" while filtering nothing; the admin search does the same. Long strings, emoji and pasted content are untested in labels and counts. A refresh mid-flow silently drops the simulated role (documented in `session.jsx`, but the UI never warns).

**Casey (Distracted Mobile)** — Five top-level nav items plus a dropdown is a lot for a small screen; the primary CTA in hero and admin sits at the top of the viewport rather than the thumb zone. Tap targets are, to their credit, 44px+.

## Minor Observations

- `.primary-nav > a:not(.button)` and `.nav-dropdown__trigger` hard-code `#4d5a70` instead of a token.
- `.eyebrow` at 0.73rem/700 passes AA on white, so no change needed — but confirm across the dark `auth-aside`/`portal-welcome` variants.
- The `SearchField` sets focus styling on the inner `input` (inset shadow) rather than the visible wrapper, so the focus ring looks weaker than the global one.
- `profile-form > .form-field:nth-last-of-type(1):has(textarea)` is a fragile structural selector.
- `index.html` description mentions "integração futura" in the meta description — visible to search engines as the product's own pitch.
- `app.config.ts` is TypeScript in an otherwise strict "no TypeScript" project.

## Questions to Consider

- What if the app had exactly one honest, calm sentence about data being offline — shown once — and every other screen simply showed a beautiful empty state?
- What would the homepage look like if it committed to a single path instead of offering three?
- If the route motif is the brand, why is it only in the logo and the hero — could it carry the portal and admin too?
- Does "Agendamento" belong in the global nav at all, before there is a mentor to book?
